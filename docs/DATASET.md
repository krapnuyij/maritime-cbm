## 다운로드

1. [UCI 공식 페이지](https://archive.ics.uci.edu/dataset/316/condition+based+maintenance+of+naval+propulsion+plants)의
   `Download` 링크 또는 [공식 배포 ZIP](https://archive.ics.uci.edu/static/public/316/condition%2Bbased%2Bmaintenance%2Bof%2Bnaval%2Bpropulsion%2Bplants.zip)을
   통해 파일을 내려받는다.
2. ZIP 내부의 `UCI CBM Dataset/` 폴더를 찾는다. `__MACOSX/`와 `.DS_Store`는 사용하지 않는다.
3. `data.txt`, `README.txt`, `Features.txt`를 `data/raw/uci_cbm/` 아래에 복사한다.
4. 세 파일의 이름과 내용을 변경하지 않는다.
5. 최초 검증 시 사용한 원본 파일의 SHA-256 해시를 이 문서의 `실제 검증 결과`에 남긴다.

`data/raw/`와 `data/processed/`는 Git에서 제외된다. 이 저장소에는 UCI 원본 데이터를
커밋하지 않는다.

예상 로컬 구조는 다음과 같다.

```text
data/raw/uci_cbm/
├── data.txt
├── Features.txt
└── README.txt
```

파일을 배치한 뒤 다음 명령을 실행한다.

```bash
uv run python -m maritime_cbm.data.validation
```

검증 성공 시 파일 크기와 SHA-256, 행·열 수, 격자 고유값 수, 상수·중복 열과 `lp`–`v`
관계가 JSON으로 출력된다. 필수 파일, 행·열 수, 숫자·유한값, 공식 격자 또는 전체 조합이
맞지 않으면 실패한다. 상수 열, 동일 열과 `lp`–`v` 1:1 관계는 실패가 아니라 후속 모델링
결정을 위한 관찰 결과로 기록한다.

`data.txt`에는 헤더가 없으므로 검증 모듈은 공식 스키마 순서대로 열 이름을 부여한다.
실제 변수 순서가 맞는지는 함께 배포된 `Features.txt`와 `README.txt`를 이 문서의 변수 목록과
별도로 대조해 확인한다.

## 공식 설명 기준 검증값

- 행 수: 11,934
- 열 수: 입력 16개와 정답 2개를 합한 18개
- 운항 속도: 3~27 knots, 3 knots 간격, 고유값 9개
- `kMc`: 0.950~1.000, 0.001 간격, 고유값 51개
- `kMt`: 0.975~1.000, 0.001 간격, 고유값 26개
- 전체 격자: 9 × 51 × 26 = 11,934행

부동소수점 격자는 직접 equality 비교하지 않고 허용오차 또는 반올림을 적용해 검증한다.
실제 파일의 행·열 수, 변수 순서와 격자 구조가 공식 `README.txt`와 다르면 모델링을
중단하고 원인을 먼저 기록한다.

## 모델 입력 특성

원본 16개 입력은 보존하고, 모델 학습·추론에는 다음 구조적 특성을 제외한 12개 입력을
공통 순서로 사용한다.

| 제외 특성 | 근거 | 유지 특성 |
|---|---|---|
| `T1` | 전체 데이터에서 상수 | 해당 없음 |
| `P1` | 전체 데이터에서 상수 | 해당 없음 |
| `Tp` | `Ts`와 완전히 동일 | `Ts` |
| `lp` | `v`와 1:1 대응 | 물리적 단위가 명확한 `v` |

제거 근거는 전체 시뮬레이터 격자의 구조적 사실이며 정답이나 테스트 성능을 사용해 선택한
것이 아니다. 제거 목록은 `schema.py`에서 중앙 관리하며 학습과 추론은 같은 특성 선택 함수를
사용한다. M5 상태 추정 API도 원본 16개가 아니라 아래 순서의 12개 이름을 직접 입력받는다.

```text
v, GTT, GTn, GGn, Ts, T48, T2, P48, P2, Pexh, TIC, mf
```

M5 입력 범위 계약은 배포 대상 M3 모델이 학습한 기본 상태 그룹 train 8,352행을 기준으로
한다. `v`는 연속 범위가 아니라 `{3, 6, 9, 12, 15, 18, 21, 24, 27}` knots 중 하나여야
한다. 나머지 11개 센서의 양 끝을 포함한 관측 범위는 다음과 같다.

| 입력 | 최솟값 | 최댓값 |
|---|---:|---:|
| `GTT` | 253.547 | 72784.872 |
| `GTn` | 1307.675 | 3560.741 |
| `GGn` | 6589.002 | 9797.103 |
| `Ts` | 5.304 | 645.249 |
| `T48` | 442.364 | 1115.797 |
| `T2` | 540.442 | 789.094 |
| `P48` | 1.093 | 4.560 |
| `P2` | 5.828 | 23.140 |
| `Pexh` | 1.019 | 1.052 |
| `TIC` | 0.000 | 92.556 |
| `mf` | 0.068 | 1.832 |

이 범위를 전체 11,934행과 네 시나리오의 validation·test 8개 역할에 적용했을 때 범위 밖
행은 모두 0개였다. 이 값은 실제 선박의 물리적 안전 범위가 아니라 시뮬레이션 데이터와
배포 모델의 학습 지원 범위를 나타낸다. M5 API 계약은 범위 밖 값을 clipping하지 않고
`422`로 거부하도록 정한다.

## 데이터 분할

모든 행 인덱스는 0부터 시작하는 `data.txt` 원본 행 순서의 위치다. 난수를 사용하는 행 랜덤
분할과 상태 그룹 분할은 각각 함수 내부에서 독립적인 `numpy.random.default_rng(42)`를 생성해
호출 순서의 영향을 받지 않게 했다.

### 비교용 행 단위 랜덤 분할

전체 행의 permutation에서 앞 1,790행을 테스트, 다음 1,790행을 검증, 나머지 8,354행을
학습에 배정한다. 이 분할은 비교용 기준이며 일반화 성능의 주된 근거로 사용하지 않는다.

### 기본 상태 그룹 분할

`round(kMc × 1000)`, `round(kMt × 1000)` 정수 쌍을 사전순으로 정렬해 1,326개 그룹 ID를
부여한다. `kMc`가 950 또는 1000이거나 `kMt`가 975 또는 1000인 경계 그룹 150개는 모두
학습에 고정한다. 내부 그룹 1,176개에 permutation을 적용해 앞 199개를 테스트, 다음
199개를 검증, 나머지 778개를 학습에 배정한다.

| 역할 | 전체 그룹 수 | 행 수 |
|---|---:|---:|
| 학습 | 928 | 8,352 |
| 검증 | 199 | 1,791 |
| 테스트 | 199 | 1,791 |

각 상태 그룹은 9개 운항 속도를 모두 포함한다. seed 42의 테스트 그룹 199개 모두가 학습
그룹과 Chebyshev 거리 1인 8-이웃을 하나 이상 가지며, 197개(98.995%)는 축 방향 4-이웃
학습 그룹을 하나 이상 가진다. 모든 인접 상태가 학습에 있다는 보장은 없으므로 이 분할은
엄격한 보간이 아니라 `격자 내부 상태 일반화 평가`로 표현한다.

### 연속 열화 구간 holdout

부동소수점 equality 대신 1,000을 곱해 반올림한 정수 계수로 경계를 비교한다.

| 시나리오 | 학습 | 검증 | 테스트 | 행 수(학습/검증/테스트) |
|---|---|---|---|---:|
| 압축기 | `kMc` 0.960~1.000 | `kMc` 0.955~0.959 | `kMc` 0.950~0.954 | 9,594 / 1,170 / 1,170 |
| 터빈 | `kMt` 0.985~1.000 | `kMt` 0.980~0.984 | `kMt` 0.975~0.979 | 7,344 / 2,295 / 2,295 |

두 시나리오는 학습에서 보지 못한 계수 값이 낮은, 즉 열화가 더 심한 방향의 외삽을
평가한다. 압축기와 터빈 시나리오는 학습량과 외삽 거리가 다르므로 성능을 직접 비교하지
않는다. 검증 구간은 학습 구간에 인접해 테스트 구간보다 쉬울 수 있다.

강건성 평가에서는 holdout 대상인 압축기 시나리오의 `kMc`와 터빈 시나리오의 `kMt`에
대해 MAE와 RMSE를 주지표로 사용한다. 좁은 테스트 정답 범위에서는 작은 오차에도 R²가
크게 낮아질 수 있으므로 R²는 해당 대상에 한해 보조 지표로 해석한다. 반대편 정답은 전체
범위를 포함하므로 일반적인 R² 해석이 가능하다. 트리 계열 모델이 학습 범위의 최솟값에서
포화될 가능성은 M2 오류 분석에서 확인한다.

### 분할 해시

각 역할의 정렬된 행 인덱스를 NumPy `<i8` little-endian int64의 연속 바이트로 직렬화한 뒤
SHA-256을 계산했다. 현재 `uv.lock`의 NumPy 버전은 2.5.3이다. NumPy 버전을 변경할 때는
난수 스트림 동일성을 가정하지 않고 아래 해시를 재검증·재기준화한다. 난수를 사용하지 않는
holdout도 동일한 직렬화 규칙으로 기록했다.

| 시나리오 | 학습 SHA-256 | 검증 SHA-256 | 테스트 SHA-256 |
|---|---|---|---|
| 행 랜덤 | `830e5c6ad4ef9a309336e40de92c90495dc11f7fa49a08d33065270cf077fd50` | `63ba78c446800528028b5552030d8179c5b60767be1d87dc497811b8d7a49b7a` | `fc17cf1842355c9daa35eac1e7c0b3cbf5e7154f2c0091dbce1683ae8e46648b` |
| 상태 그룹 | `158edd80d6f67c91405d34d20a7657fb29557536893e996758bf6e884e0a0917` | `84ac9e1059e569e4085825061a4c549d3dda1042d5a608fe89dcc1e7ca01d997` | `88bfc5b3cf14be31f862936ecfc9f7fe3663a8bd953a95270feb0934392ccbfe` |
| 압축기 holdout | `a0af865d4f671fe7ed56e77b3da3547646451a9027ad714f5e4a8c578c5c326a` | `b40891ddb6b4e822958517ffb7f90265ddffc752c52d8162e34584143644848d` | `e180abb2ca8bcefd29840d4a221966a6a4220ccf8bd66fc1184a1df96ba3a6c2` |
| 터빈 holdout | `a074708beb2ec894011265993fd3077f36ef686321d9badfce6fac516a0fb79e` | `dc49fecf576259f83e10fbeca6cdf0fcd48f758a21965cd4d38602860be46c55` | `cd1e52f7efdd68ca4ec4f3f9d818315bc1fa816aa1d9a44854b2fd809d87a180` |

해시는 원본 파일이 있을 때 실행되는 통합 테스트 상수로도 고정했다. 실제 행 목록은 대용량
중간 산출물이므로 저장소에 커밋하지 않고 같은 함수로 재생성한다.

## EDA 산출물

전체 데이터의 구조·격자 집계에는 전체 행을 사용하고, 센서와 정답의 관계는 기본 상태 그룹
분할의 학습 행만 사용한다. 테스트 행은 특성·모델·임계값 선택에 사용하지 않는다. 집계 CSV와
핵심 그림은 [`reports/eda/`](../reports/eda/)에 있으며 재생성 명령도 같은 위치에 기록했다.

학습 행의 모든 센서와 `kMc`, `kMt` 사이 pooled Pearson 상관은 절댓값 0.048 이하다.
하지만 운항 속도별로 나누면 다음 관계의 Pearson 상관 절댓값 중앙값이 크게 나타난다.

| 관계 | 속도별 Pearson 상관 절댓값 중앙값 |
|---|---:|
| `T2`–`kMc` | 0.934 |
| `P2`–`kMt` | 0.948 |
| `GTT`–`kMc` | 0.837 |

속도별 센서·정답 상관 절댓값의 전체 최댓값은 0.992다. 센서 분산 중 속도별 평균 차이가
차지하는 비율도 `GTT` 0.999, `P2` 0.999, `mf` 0.996, `T48` 0.977로 나타났다.
이는 운항 속도 차이가 센서 변동을 지배해 열화 상태와의 관계가 pooled 상관에서 가려질 수
있음을 뜻한다. 센서가 열화 계수와 무관하다는 근거로 해석하지 않는다.

M2에서는 원시 센서에 단순 선형 모델을 적용할 때 불리할 가능성을 고려하고, 운항 조건을
반영한 특성·상호작용 또는 속도 기준 정규화 후보를 학습 데이터 안에서 검토한다. 위 수치는
모델 성능이 아니라 EDA 관찰 결과다.

## 해석 제한

이 데이터는 타임스탬프가 없는 정상상태 시뮬레이션 데이터다. `kMc`, `kMt`는 실제 고장
